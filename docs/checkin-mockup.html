What this demonstrates

  1. Booking lookup — guest enters a confirmation code; the tablet already knows the room, dates and stay length once matched.
  2. Guest details — confirms name/contact against the booking, doesn't re-collect from scratch.
  3. ID verification — sighted/captured for verification, not retained by default (see risk & compliance matrix).
  4. Consent — explicit acceptance of house rules and the privacy notice, recorded against the stay.
  5. Room + access code — issued automatically once check-in completes; the same booking-linked entitlement can also unlock guest Wi‑Fi (see Wi‑Fi project).
  6. Confirmation — closes the loop with a clear "you're in" state, same pattern as the Wi‑Fi captive portal mockup.

This is a front-end simulation only — no booking system, ID verification service, or backend is connected. See Guest Operations & Digital Check‑in for the full design and hardware options.
