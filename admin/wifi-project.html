Starlink plan and monitoring implications

Priority plan required for hotspot resale

Current Starlink terms expressly allow third-party hotel/community hotspot resale when the customer purchases a Priority Plan. This is the key contractual gate before charging guests.

Australian Local Priority data

The Australian Critical Information Summary lists Local Priority tiers and included priority-data allowances. The small 50 GB tier is not a realistic assumption for a streaming-heavy multi-room guest service without testing what happens after the allowance is consumed.

Enterprise dashboard

Starlink's business dashboard exposes online/offline state, alerts, obstruction, ping drop, latency, client/router data, throughput, software version, uptime and last-online status, plus remote reboot and some Wi‑Fi configuration controls.

API access is not guaranteed

Starlink documents an account/data API, but its own support material says API access is provided to larger business customers. Integrate the official API if this account is eligible; otherwise use the Enterprise Dashboard plus the managed internal-network controller/API for monitoring.

Network architecture

Starlink / approved business backhaul → gateway/firewall → managed switches/APs → segregated networks.
Guest SSID → captive portal → voucher/payment/booking entitlement → internet.
Operations SSID/VLAN → check-in tablet, staff/admin devices, payment integrations and management systems.
IoT / fixed-equipment VLAN → smart TVs, CCTV cameras, environmental sensors and future building systems. These remain permanently provisioned and never see the guest captive portal.
Management plane → Sentrix Digital monitoring/controller → service health, AP status, connected infrastructure, alerts, remote changes and troubleshooting.

Captive portal — guest access only

What it is

The captive portal is the branded page a guest sees after joining the guest Wi‑Fi network. It validates a voucher or paid booking entitlement before the gateway opens internet access.

What it is not

It is not the network login for televisions, cameras, sensors, staff systems or reception equipment. Those devices receive permanent managed credentials on separate network segments.

Multi-device

The entitlement belongs to the guest/booking, not to a single phone. A token can enrol multiple authorised devices with a configurable device/concurrency limit.

Automatic expiry

Access expires at the package end or checkout unless management deliberately extends it. The booking system and captive-portal backend share entitlement state.

Pay for Wi‑Fi during check-in

Booking matched → guest/room/stay length known.
Wi‑Fi offered → check-in tablet highlights the package closest to the booked stay.
Guest taps card/wallet → separate integrated EFTPOS terminal handles the payment.
Payment approved → provider event/API returns to backend → entitlement/token generated against guest + booking + room + validity.
Immediate activation → token/QR shown and sent; captive portal sees the same booking-linked entitlement.

The proposed Lenovo LTE tablet should not be treated as an NFC payment terminal. Use a certified integrated EFTPOS device (for example Square Terminal via Terminal API or an Australian integrated EFTPOS solution such as Tyro) and keep card data out of the Fawkner/Sentrix application.

Monitoring & remote administration

Starlink layer

Monitor WAN online/offline state, alerts, latency, packet loss, obstruction, throughput, data usage, uptime and software state using the Enterprise Dashboard and official API if the account is eligible.

Internal network layer

Use managed switches/APs/mesh with a cloud or self-hosted controller exposing device health, AP/client load, VLAN state, firmware and remote configuration. This should be vendor/API-capable rather than consumer-only mesh hardware.

Application layer

Monitor captive portal availability, payment webhooks, token issuance, entitlement failures, check-in integration and database health.

Alerting

Backend raises actionable alerts to Sentrix when WAN, AP, captive portal or payment components fail. Routine issues should be resolved remotely; physical intervention is the exception.

Key risks / decisions

High

Wrong Starlink plan

Charging hotel guests on a non-authorised plan risks breaching Starlink terms. Priority/resale authorisation is a launch gate.

High

Under-sized data plan

A low-cost Priority allowance may be exhausted quickly by streaming/multi-device use. Measure traffic before treating low plan cost as permanent.

Medium

API assumption

Starlink's official API access is not guaranteed to a single small-business account. The design must remain operable through the dashboard and internal-network telemetry.

Medium

Operator dependency

Sentrix should own operational accountability, but credentials, documentation, source code/config exports and transition rights must ensure the owners can transfer the service if the agreement ends.
